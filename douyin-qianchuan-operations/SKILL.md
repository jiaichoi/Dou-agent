# 抖音巨量千川实操

把经营目标、后台证据和商品利润转成能执行、能复盘的投放动作。默认中文，先给判断及下一步，再解释依据。输出建议不代表已经改动账户。

## 开始工作

1. 从用户问题选择任务：手册方法查询、投前测算、冷启动/测款、诊断、预算出价、素材/人群、乘方组合、全域/商品卡、旺季计划、日报或能力自检。已有信息直接使用，不让用户重填问卷。
2. 优先读用户已打开的千川后台和指定货盘/经营表。先核对店铺、账户、日期与筛选条件；先记录原始字段名再解释。工具不可用时说明缺少什么，提供仍可完成的分析，不编造数据。
3. 明确商品ID与ERP货号映射、推广场景（直播/商品等）、页面所示产品及优化目标。不要将旧标准推广的操作菜单、人群设置或计划数量套到当前全域产品。
4. 只补问影响当前决定的缺口。例如给具体预算前需要预算上限及可承受试错损失；判盈亏前需要同口径成本。缺口不影响的素材检查、数据质量检查可继续。

## 按需读参考

- 算保本线、解释支付/净成交ROI、判断利润：读 [经营口径](references/economics.md)，必要时使用 `scripts/economics.py`。
- 建计划、测款、调价、诊断、放量、素材迭代：读 [操作流程](references/playbook.md)。
- 交付日报、试验表、具体调整方案：读 [交付模板](references/templates.md)，只选当前需要的表。
- 查询或应用任何手册方法：先读 [全册覆盖与检索](references/manual/index.md)，再按问题读取对应章节。00—11全部有逐章记录，包含正文、表格与59个画板信息。不要只读本入口或通用流程就回答详细打法。
- 判断不同章节数值是否一致：读 [冲突清单](references/manual/conflicts.md)，同时核对相关章节。
- 查询平台变更、来源版本和核验状态：读 [来源与适用边界](references/sources.md)。

## 完整调用手册的方法

1. **问手册怎么讲**：先准确给作者方法，包含前提、预算、时间、数量、阈值、成功/失败分支、案例及适用对象；再简短指出相关冲突和未证实项。不能用通用建议替换用户所问方法，也不能因有争议就隐去原内容。
2. **问现在怎么做**：先读取相关逐章记录，再对照当期后台、货号利润、库存与投入授权，将手册方法变成可检验行动。明确哪些来自手册、哪些是当前数据支持的选择。
3. **问所有信息/完整更新**：按覆盖清单逐项遍历，保留正文、表格、图内小字、前提、失败分支、口诀、自检及更新说明；不把仅查看目录标为读完。原文缺失的定义、分母、阶段或证据注明缺口，不补造。
4. **问学习实操**：用00六条学习路径及11的5+7+7自检安排练习；每项给输入、操作、产物和验收标准。手册阈值是训练参考，不是平台统一考核。

快速定位：01基础；02冷启/赛马/单线/少计划；03出价/锁ROI；04定向/同行；05素材七步与脚本；06诊断/放量转控本；07避坑/保障；08乘方/双轨/同频/阶梯；09内容货架/单品；10恒源祥季节方案；11逐图流程及时间预算表。具体文件链接见索引。

## 决策约束

- 区分【后台事实】【货盘/财务事实】【手册经验】【经营推断】。引用数据注明日期、字段口径和层级；行业案例不作为本店事实。
- 平台规则、产品入口、归因窗口、成本保障及费率在使用时核对当前官方说明和当前账户页面；无法核对就标待确认。官方搜索入口见来源文件，不把课程目录当成具体规则证据。
- 先检查口径、数据成熟度及样本，再判断利润和漏斗瓶颈。不要因为ROI高就关停，也不要因为小时消耗低就重建。
- 预算、目标ROI、CPA各有含义：预算是可消耗上限，目标ROI不是保本利润承诺。设低ROI可能换取探索，但不能据此假定会起量或盈利。
- 一次尽量只检验一个主要变量；保留原值、改动时间、观察窗口和停止条件。小样本、不同时段和同时多项改动不能支持确定性因果结论。
- 账户/全域成交、计划成交、素材成交可能重叠；不可跨层级直接相加，也不能把全域成交全部称为广告带来的增量。
- 服饰按货号、男女款及必要的SKU拆解。缺码、库存、价格、优惠、评价、退货原因和直播承接必须纳入放量判断；不只盯广告指标。
- 读取私有手册时按章浏览，按当前任务保留完整知识要点和来源定位，不频繁复制、读剪贴板或导出原文。未读章节、未能辨认的画板要如实记录。

## 从判断到执行

每条核心动作写清：**对象 → 证据 → 动作与参数 → 预算/损失边界 → 观察窗口 → 达标/停止条件 → 复查时间**。

仅有“帮我分析/做技能/给方案”时完成分析或方案；用户明确要求操作且账户、对象及额度范围清楚时按授权执行，不重复询问。发布计划、启停或调整预算前核对完整变更清单与当前授权，遵循当前工具的确认要求。超出授权范围时只暂停有关动作。

操作后回读页面或可靠接口，确认实际值及状态。审核中、草稿、提交失败分别报告；没有回读证据不声称已生效。没有执行操作时明确交付的是建议。

## 结束前核验

- 结论有数据或明确假设支撑，空白数据未填成零。
- 保本线与被比较的ROI使用同一分子、费用边界及订单范围。
- 手册方法的问题已答到完整条件和分支；实际建议没有把固定预算、通用门槛或ROI盈亏线直接当本店事实。
- 计划覆盖投入上限、承接条件、试验变量和退出条件。
- 清楚区分已读取、已计算、已执行和仍待验证。
