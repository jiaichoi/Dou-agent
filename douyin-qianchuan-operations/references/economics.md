# 经营口径与保本计算

## 先确定范围

记录账户、货号、日期、订单归属口径、退款观察截止时间、广告费用范围、归因窗口和报表字段定义。当天支付订单与当天退款通常不是同一批订单，不可随意相减来评价当天获客效果。

支付ROI = 支付金额 / 广告消耗。净成交ROI按后台字段定义计算；只有退款与支付属于同一统计范围时，才可使用 `(支付金额 - 对应退款金额) / 广告消耗`。已用净成交金额时不要再次乘以退款折损。

CTR需明确点击类型及曝光分母；CVR需明确支付订单、支付人数或下单人数与哪个点击分母对应。不同定义的指标不作直接排名。

## 可复核模型

以下是经营核算模型，不冒充平台归因规则。输入同一订单范围的金额：

- P：支付金额（商家口径，平台补贴另核对，避免重复算收入）。
- R：这批订单截至观察日的退款金额。
- N = P - R：净收入；若不是实际结算收入，注明差异。
- C：这批订单的非广告成本，采用净额且不重复记账。至少逐项核对留存商品成本、退件损耗、正逆向运费、包装、平台费、佣金及其他实际适用费用。可再加分摊固定费用。
- M = N - C：广告前贡献额。
- A：同范围广告消耗。
- 广告后贡献 = M - A。未包含税费/工资/固定成本等项目时，不称最终净利润。
- 支付口径保本ROI = P / M；净收入口径保本ROI = N / M，仅M > 0时有意义。
- 若M ≤ 0，即使不投广告也没有正贡献，不存在可行的正广告预算保本线。

若收入、退货率、价格或成本随放量变化，保本阈值也变化，不能用历史M保证未来盈利。退货尚未成熟时分别做实际截至日与退款上升情景。

退款商品可再次销售时不能既把完整采购成本算损失又重复扣退回库存价值。按财务实际损失入账；退款退回的平台费或佣金也使用净额。尚不明确的费用单列未知，不用零冒充已确认。

计算最大可承受成交成本时，先明确CPA分母是支付订单还是净成交订单，再用M除以对应订单数。不要用 `售价 × 毛利率 / 保本ROI` 代替这一计算。

## 工具用法

准备JSON文件，每个成本项目都明确填入已知值：

```json
{
  "scope": "演示货号，同批订单，退款已观察完成；不含固定费用和税费",
  "paid_amount": 10000,
  "refund_amount": 2000,
  "non_ad_costs": {"goods_net": 3500, "fulfillment": 500, "fees_net": 400},
  "ad_spend": 2000
}
```

从技能目录运行 `python3 scripts/economics.py /明确路径/input.json`。工具只校验数值并计算，不验证输入费用完整或订单归因正确。

此例N=8000、M=3600、广告后贡献=1600；支付保本ROI约2.7778、净收入保本ROI约2.2222。二者不同但对应同一笔经营账。跨口径比较会误判。

## 缺失信息处理

仅有售价和“毛利50%”时先问毛利是否已包含扣点、运费及退款损耗；无法确定只能做带假设的敏感性测算。禁止套用“ROI≥3就是盈利”或把某个品牌、某个货号的保本值推广到全店。
